# 📩 問い合わせ (Inquiry) モジュール詳細

## 核心ロジック: `InquiryController`
 に基づく実装事実。

### 1. オーガナイザー (対応責任者) の自動解決
* 問い合わせ対象（`target_type`）に応じて、自動的に対応すべきアーティスト/管理者を特定する。
    * **イベント:** そのイベントの主催アーティスト。
    * **注文:** 注文に含まれる商品の販売アーティスト。

### 2. ステータス管理と自動クリーンアップ
* **自動再オープン:** 解決済みでない限り、ユーザーがメッセージを送信するとステータスは自動的に `open`（未対応）に戻る。
* **ライフサイクル:** ユーザーが `close`（解決済み）にすると、1年後の削除予定日時（`expires_at`）がセットされる。

### 🚩 地雷注意
* **解決済みのガード:** `status === 'closed'` の場合、メッセージの送信（`sendMessage`）は物理的に禁止される。再開が必要な場合はステータス変更ロジックの検討が必要。
