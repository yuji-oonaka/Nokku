# 🔐 認証・認可 (Authentication) モジュール詳細

## 核心ロジック: ``AuthController``
 に基づく実装事実。

### 1. Firebase 統合認証
* **冪等な登録:** ``register`` 時は ``firstOrCreate`` を使用し、Firebase側でユーザーが作成済みであっても、DB側の重複作成を物理的に防いでいる。
* **ミドルウェア依存:** 実際のトークン検証やDB照合、``Auth::login`` の実行は ``FirebaseApiAuth`` ミドルウェアが先行して処理する設計となっている。

### 2. ロールベースのアクセス制限 (RBAC)
* **アプリ利用制限:** アプリケーションは現場・ファン向けであるため、管理専用ロールである ``operator`` のログインは API レベルで明示的にブロック(403)される。

### 🚩 地雷注意
* **IDトークンの必須性:** ``register`` は Bearer トークンが必須。これが漏洩すると偽装登録が可能になるため、HTTPS 通信の常時適用が前提である。
* **メールアドレスの同期:** Firebase 側のメールアドレスをソースオブトゥルース（真実のソース）として DB へ保存している。DB 側を直接書き換えても Firebase 側は更新されない点に注意せよ。
