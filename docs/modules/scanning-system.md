# 🔍 スキャン・入場システム (Scanning System) モジュール詳細：Ver 2.0

## 核心ロジック: `TicketAdmissionService`, `OrderScanController`

### 1. QRコードの自動判別ロジック

* **フォールバック機能:** チケットスキャン時にチケットが見つからない場合、自動的に `Order` テーブルを検索する。
* **利便性:** グッズ引換用QRをチケットモードで読み込んだ場合、適切なエラー（「グッズ引換モードにしてください」）を返却し、現場の混乱を防ぐ。

### 2. 厳格な認可プロトコルと監査ログ (RBAC & Audit)

* **スタッフ所属チェック:** `scannerUser->role` が `staff` の場合、雇用主（`employer_id`）がイベントの主催アーティスト（`artist_id`）と一致しているかを厳密に検証する。
* **二重入場・引換の防止:** `lockForUpdate` による悲観的ロックを実行し、DB更新後にレスポンスを返すことで、同一QRによる同時入場を物理的に防ぐ。
* **★【NEW】スタッフ記名性:** 現金決済や引換確定の際、`cash_confirmed_by` カラムに操作したスタッフの ID を直接記録する。これにより、誰が最終対応者であるかが永久にログとして刻まれる。

### 3. ハイブリッド同期 (MySQL & Firestore)

* **Firestore同期義務:** MySQLの更新に成功した後、必ず `syncToFirestore` を呼び出し、ユーザーアプリ側へ即座に「使用済み」を通知する。
* **リアルタイム反映:** チケットなら `ticket_status`、グッズなら `order_status` コレクションへ、スキャナーID付きで反映させる。

### 4. 在庫と定員の整合性

* **憲法準拠:** `capacity`（定員）はマスタデータとして不変、実在庫は `remaining_count` で管理する。
* **責務の分離:**
* **注文時 (OrderController):** `remaining_count` を減算して在庫を確保。
* **キャンセル時 (CancelExpiredOrders):** `remaining_count` をインクリメントして在庫を復元。
* **発券時 (TicketService):** 数量操作を行わず、チケットの実体生成のみに専念。



### 📊 【NEW】現場オペレーションの可視化 (2026/02/02 追加)

* **管理画面へのフィードバック:** スキャン結果（誰が対応したか）は、Filament 管理画面の「対応スタッフ」カラムにバッジ形式でリアルタイムに表示される。
