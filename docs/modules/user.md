# 💎 ポイント・ガシャ (Points & Gacha) モジュール詳細：Ver 2.0

## 核心ロジック: `PointService`, `GachaService`

### 1. 経済圏の原子性 (Atomic Transaction)

* **仕様**: ガシャ実行(`spin`)は単一のトランザクションで包まれています。
* **整合性**: ポイント消費、アイテム付与、重複還元、ログ出力のいずれかが失敗した場合、全てのポイント操作はロールバックされます。

### 2. 残高監査 (Balance Audit)

* **仕様**: `PointTransaction` に `balance_after` を常時記録します。
* **利点**: ユーザーの最終ポイント残高と履歴の合計が一致するか、機械的に監査可能です。

### 3. 【NEW】パラメータの動的制御 (Dynamic Configuration)

* **仕様**: ガシャごとの「消費ポイント」および「重複還元率」は、`gachas` テーブルの値を参照します。
* `spin_cost`: ガシャ1回あたりの消費ポイント。
* `refund_rate`: 重複アイテム当選時のポイント還元率（例: 0.5 = 50%）。


* **メリット**: 運営が管理画面（Filament）からリアルタイムに経済バランスを調整でき、プロモーションやイベントに即座に対応可能です。

### ✅ 解決済みの「ねじれ」

* **重複還元率の動的化**: 以前は `GachaService` に 50% がハードコードされていましたが、現在は各ガチャ固有の設定値（`refund_rate`）に基づいた計算に移行済みです。
* **フロントエンド同期**: アプリ側の表示（`GachaScreen`）も、ハードコードを廃止し、APIから取得した最新の `consumption_point` および `refund_amount` を表示するよう正常化されました。
