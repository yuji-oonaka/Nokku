# 💎 ポイント・ガシャ (Points & Gacha) モジュール詳細

## 核心ロジック: `PointService`, `GachaService`

### 1. 経済圏の原子性 (Atomic Transaction)
* **仕様**: ガシャ実行(`spin`)は単一のトランザクションで包まれている。
* **整合性**: ポイント消費、アイテム付与、重複還元、ログ出力のいずれかが失敗した場合、全てのポイント操作はロールバックされる。

### 2. 残高監査 (Balance Audit)
* **仕様**: `PointTransaction` に `balance_after` を常時記録。
* **利点**: ユーザーの最終ポイント残高と履歴の合計が一致するか、機械的に監査可能。

### ⚠️ 今後の課題（メンテナンス性）
* **重複還元率の固定化**: 現在 50% 還元が `GachaService` にハードコードされている。
* **改善案**: 将来的にガシャ毎の個別設定（DB管理）へ移行することを推奨。
