# 🎟️ イベント・アーティスト管理 (Event & Artist) モジュール詳細

## 核心ロジック: `EventController`, `TicketTypeController`, `ArtistController`
 に基づく実装事実。

### 1. イベントと券種 (TicketType) の連動
* **在庫の初期化:** 券種作成時、`remaining_count`（残り在庫）は `capacity`（定員）と同じ値で初期化される。
* **定員調整ロジック:** 定員（`capacity`）が変更された場合、売れ済みの枚数を考慮して `remaining_count` が自動調整される。既に販売済みの枚数以下に定員を減らそうとすると 422 エラーを返す。

### 2. アーティスト表示の最適化
* **データ制限:** アーティスト詳細（`show`）では、パフォーマンス保護のため「最新の投稿 10件」「イベント 5件」「商品 8件」のみを取得する制限（`take`）が実装されている。
* **フォロー機能:** `syncWithoutDetaching` を使用し、二重登録を防ぐ安全な実装となっている。

### 🚩 地雷注意
* **過去イベントの保護:** `UpdateEventRequest` や Policy により、開催済みのイベント内容を安易に変更できないガードがあることを前提とせよ。
* **個人情報の除外:** アーティスト一覧（`index`）では `password` や `email` を `select` から明示的に除外している。フィールド追加時に漏洩させないよう注意。
